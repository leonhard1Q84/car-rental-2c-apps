版本：v1.3；日期：2026-11-04；模式：Full。

- **所属模块**：`home`
- **拆分来源**：`specs/feature/customer-service-hub.md` v1.0（2026-11-03 按产品模块拆分，正文未改写）

## 1. 范围与来源

适用于 customer lane。业务来源为 2026-11-03 至 2026-11-04 产品指令：默认应用直接进入客户订单验证；首页使用每行三格、共两行的应用宫格，依次展示 Online Check-in、快速取车、自助取还、续租、投诉建议、更多应用。快速取车服务常规租车订单，自助取还服务自助取还订单，两项不是互相替代或动态切换的应用；订单类型仅控制对应入口准入。

客户基线使用已迁入的 Codeup `main@d6e5b1c` 的 pickup-preparation，身份、取车验车与原合同签署继续遵循《取车前准备》与《在线验车》。本规格替代原目录入口、四项网格和电话续约的呈现要求。本次续租调整不改变首次取车合同签署。

## 2. 角色、入口与成功标准

客户访问 `/` 或 `/selfservice.html` 进入 PickupPreparationApp 的订单号＋预订电话后四位验证；`?flow=pickup-preparation` 保持兼容。历史自助取还预览显式使用 `?flow=selfservice`。显式 step 评审链接属于本地导航，不构成生产鉴权。

应用划分以 [客户应用边界](../../epic/customer-applications.md) 为准；快速取车是常规租车订单的到店前车辆照片确认与合同签署能力；自助取还包含押金、验车、合同、电子钥匙／车控、取还车与评价。投诉建议当前复用既有外部反馈表单，不代表完整投诉处理应用已上线。验证页以 [统一订单验证页](../auth/booking-verification.md) 为准。

验证成功 Replace 到 home，保留相同订单草稿。Online Check-in Push 到 drivers；快速取车 Push 到 pickup；自助取还进入既有 `?flow=selfservice` 完整应用；续租 Push 到 renewal；投诉建议在新标签打开既有外部表单；更多应用点击说明后续能力仍在规划中。

## 4. 首屏、字段分组与导航

首页：品牌标题及语言入口 → 预订摘要 → 每行三格的两行应用网格。第一行为 Online Check-in、快速取车、自助取还；第二行为续租、投诉建议、更多应用。重要且已存在的续租与投诉建议保持首页直达；更多应用仅为后续规划应用保留入口，点击以 Dialog 说明尚在规划，不展示虚构功能。

快速取车与自助取还入口始终同时可见。常规租车订单仅允许进入快速取车，自助取还入口轻度灰显但可点击查看“仅适用于自助取还订单”；自助取还订单仅允许进入自助取还，快速取车入口轻度灰显但可点击查看“仅适用于常规租车订单”。订单类型来自已验证订单会话；本地 fixture 仅用于演示，不可视为生产判断规则。

### 4.1 验证其他订单与本地演示重置

来源：2026-11-03 产品负责人指令及首页截图；仅适用于本仓库 Mock 演示，截图不代表生产事实。

- [DEL] 首页页头移除“重新查询”按钮，保留语言切换。
- [MOD] 底部“验证其他订单”是切换入口。点击后，先等待当前保存完成；未配置鉴权、自助取还或续租 API 时，清除当前 Mock 订单处理进度，再 Replace 到空白验证表单。重新验证同一账号后恢复该账号初始 fixture，包括原有未开始、驳回、通过及续租预置场景。
- 清除范围：当前订单的准备草稿、客户上传材料、资料提交及补正记录、条款确认、各版本验车确认、签署及合同文件、续租演示申请与处理结果。门店提供的车辆资料快照作为独立输入保留；其他订单不受影响。普通页面刷新继续恢复草稿。
- 重置中禁用重复点击，使用现有 `prepSaving` 文案；失败停留首页，就地显示 `prepStorageError`，允许再次点击重试。API 模式只退出订单验证会话，不清除业务记录。
- 沿用 `prepSwitch / prepSaving / prepStorageError` 六语资源，无新增系统文案；不新增权限请求或手势。

## 8. BDD 验收

- AC-HUB-01：Given 默认或兼容入口，Then 直接展示订单验证，成功后显示预订摘要及六项应用入口，第一行三项核心办理应用，第二行续租、投诉建议与更多应用。
- AC-HUB-02：Given 六语及320px屏幕，Then 三列网格文案完整换行且不横向溢出；快速取车和自助取还同时可见并按订单类型独立门禁。
- AC-HUB-03：Given 首页，Then 页头无“重新查询”，底部保留“验证其他订单”。
- AC-HUB-04：Given 当前 Mock 订单已有处理记录，When 点击“验证其他订单”并重新验证同一账号，Then 恢复该账号初始 fixture；旧签署、验车确认和续租结果不再恢复，其他订单及门店资料快照保留。
- AC-HUB-05：Given 重置处理中或保存失败，Then 禁止重复提交；失败留在首页显示可重试错误，成功后验证表单的订单号与电话后四位均为空；配置 API 时仅退出会话。
- AC-HUB-06：Given 首页，Then 续租与投诉建议均可直接操作；点击更多应用仅说明后续应用仍在规划，不把已上线入口重复收纳。

## 9. 验证与审计边界

运行边界、类型、客户回归与构建；命令级回归覆盖时区、范围、完整租期载荷、风险拒绝自动支付、人工接受/拒绝、占位到期、付款未知恢复、合同支付门槛与 API 会话绑定。禁止 AI 浏览器交互，手机交互由人工验收。
