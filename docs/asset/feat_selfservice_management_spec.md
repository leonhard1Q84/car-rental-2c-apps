# SPEC: selfservice_management_spec_v1.0.md

## 1. 需求背景

自助取还服务，旨在打破门店营业时间限制，实现24小时车辆资源供应，提升用户取还车灵活性与便利性；为后续无人化、虚拟门店等业务模式奠定基础。
前置条件：对于特定的 OTA 渠道，SaaS 系统已确定合作，可通过 API 对接，支持自助取还业务，包括：在自助取还服务范围内展示车辆资源，资源上加自助取还 tag，自助取还服务作为一个 add_on 在 ota 渠道的资源详情中展示。对于选购（对于超出常规门店服务范围的 POI 搜索且在自助取还服务范围内的订单，该 add_on为必选）该能力的 reservation 预订订单，客户可在该渠道APP 的订单详情中，通过对接的 API 进入到SaaS 的自助取还H5 应用页面。
与常规附加设备及服务（如 ETC 卡、婴儿座椅等）不同，自助取还服务的服务范围和计费逻辑存在明显差异，故需要独立的配置和管理。


## 2. 目标（To-Be）与非目标
### 2.1 目标
1. 商户端需支持自取取还服务区域配置（包括非服务区域）；
2. 商户端需支持自助取还定价规则配置；
3. 商户端需支持自助取还服务时段配置（包括非服务时段）；
4. 商户端需支持自助取还车辆准备时间配置；
5. 商户端需支持自助取还设备管理（包括车机设备管理、设备绑定、设备状态监控等）；
6. 商户端需支持在线支付账号配置（基于 stripe connect能力）；
7. 商户端需支持自助取还订单的管理（包括自助取还订单标识、自助取还的投递、收车任务管理、在线费用登记和结算（预授权押金抵扣、off session在线支付））


### 2.2 非目标（本期不做）
- 暂不考虑由于自助取还，车辆在服务区范围内飘，动态规划处理线下车辆调度的问题。

| US-008 | 车队运营人员| 我希望能够**查看多门店服务区域交集**，以便了解服务范围重叠情况| 地图上显示多个门店的服务范围，交集区域清晰可见 |


## 4. 术语定义

| 术语 | 定义 |
|------|------|
| 自助取还服务 | 允许客户在门店营业时间外，通过H5应用自助完成车辆取还的服务能力 |
| 服务区域 | 以门店为中心，半径100km范围内可提供自助取还服务的区域 |
| 非服务区域 | 在服务区域内，通过画笔工具绘制的不提供服务的特定区域，与特定门店关联 |
| 服务区域交集 | 多个门店的100km服务范围存在重叠的区域 |
| 基础价 | 自助取还服务的起步价格，对应第一档距离范围（默认0-10km） |
| 阶梯计价 | 超出基础价距离范围后，按公里数分段计费的定价方式 |
| 导航距离 | 通过Google API路径规划计算的车辆行驶最短距离 |
| 单程总距离 | 取车点到门店的距离 + 还车点到门店的距离 |
| 计费距离 | 单程总距离 × 2（因需计算投递和收车两段服务成本） |
| POI | Point of Interest，兴趣点，指客户搜索的取还车地点 |
| Add-on | 附加服务选项，客户可选购的额外服务 |
| 预授权押金 | 订单开始前冻结的保证金，用于后续费用抵扣 |
| Off Session支付 | 无需客户在线操作的后台自动扣款方式 |
| 非营业时段 | 门店常规营业时间设置，非7×24小时服务时，指定时段内不接受自助取还订单 |
| 暂停营业时段 | 临时性的停止服务时间段，如春节维护、设备检修等特殊时期 |
| 车辆准备时间 | 一辆车衔接两个订单中间的最小整备时间，包括收车、清洁、检查、投递等环节所需时间 |



## 5. 数据模型

### 5.1 自助取还服务配置（SelfServiceConfig）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | String | 是 | 配置ID |
| store_id | String | 是 | 门店ID |
| status | Enum | 是 | 状态：active/inactive |
| service_radius | Number | 是 | 服务半径，固定100km |
| vehicle_prep_time | Number | 是 | 车辆准备时间（小时），默认6小时 |
| created_at | DateTime | 是 | 创建时间 |
| updated_at | DateTime | 是 | 更新时间 |

**业务约束**：
- 一个门店仅允许存在1条自助取还区域配置规则
- 服务半径固定为100km，不允许修改
- 车辆准备时间默认为6小时，可根据门店实际情况调整（范围：2-24小时）
- 车辆准备时间用于订单排期，确保两个订单之间有足够的整备时间

### 5.2 定价规则（PricingRule）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | String | 是 | 规则ID |
| config_id | String | 是 | 关联的服务配置ID |
| tier_order | Number | 是 | 阶梯顺序（1,2,3...） |
| distance_from | Number | 是 | 起始距离（km） |
| distance_to | Number | 是 | 结束距离（km） |
| pricing_type | Enum | 是 | 计价类型：fixed/per_km |
| price | Number | 是 | 价格（日元） |
| created_at | DateTime | 是 | 创建时间 |

**业务约束**：
- 第一条规则（tier_order=1）必须为fixed类型，作为基础价，默认0-10km
- 后续规则为per_km类型，支持阶梯计价
- 定价范围不超过100km
- 距离范围不能重叠

**示例**：
```json
[
  {
    "tier_order": 1,
    "distance_from": 0,
    "distance_to": 10,
    "pricing_type": "fixed",
    "price": 500
  },
  {
    "tier_order": 2,
    "distance_from": 10,
    "distance_to": 30,
    "pricing_type": "per_km",
    "price": 5
  },
  {
    "tier_order": 3,
    "distance_from": 30,
    "distance_to": 100,
    "pricing_type": "per_km",
    "price": 3
  }
]
```

### 5.3 非服务区域（ExclusionZone）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | String | 是 | 区域ID |
| config_id | String | 是 | 关联的服务配置ID |
| store_id | String | 是 | 关联的门店ID |
| zone_name | String | 是 | 区域名称（如"热河区"、"Airport Restricted Zone"） |
| geometry | GeoJSON | 是 | 区域几何数据（多边形） |
| created_at | DateTime | 是 | 创建时间 |

**业务约束**：
- 每个非服务区域必须关联到特定门店
- 非服务区域的几何范围应在关联门店的100km服务半径内
- 同一门店可配置多个非服务区域

### 5.4 营业时段配置（BusinessHours）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | String | 是 | 配置ID |
| config_id | String | 是 | 关联的服务配置ID |
| is_24_7 | Boolean | 是 | 是否7×24小时服务 |
| weekly_schedule | JSON | 否 | 每周营业时间表（当is_24_7=false时必填） |
| created_at | DateTime | 是 | 创建时间 |

**weekly_schedule结构示例**：
```json
{
  "monday": [{"start": "08:00", "end": "22:00"}],
  "tuesday": [{"start": "08:00", "end": "22:00"}],
  "wednesday": [{"start": "08:00", "end": "22:00"}],
  "thursday": [{"start": "08:00", "end": "22:00"}],
  "friday": [{"start": "08:00", "end": "22:00"}],
  "saturday": [{"start": "09:00", "end": "20:00"}],
  "sunday": [{"start": "09:00", "end": "20:00"}]
}
```

**业务约束**：
- 当is_24_7=true时，接受所有时段的自助取还订单
- 当is_24_7=false时，必须配置weekly_schedule
- 非营业时段内不接受新的自助取还订单

### 5.5 暂停营业时段（SuspensionPeriod）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | String | 是 | 时段ID |
| config_id | String | 是 | 关联的服务配置ID |
| store_id | String | 是 | 关联的门店ID |
| start_date | Date | 是 | 开始日期（yyyy-MM-dd） |
| end_date | Date | 是 | 结束日期（yyyy-MM-dd） |
| reason | String | 否 | 暂停原因（如"春节维护"、"设备检修"） |
| created_at | DateTime | 是 | 创建时间 |

**业务约束**：
- 暂停时段优先级高于常规营业时段
- 支持配置多个暂停时段
- 暂停时段可跨天、跨周、跨月



## 6. 功能需求

### 6.1 自助取还区域配置

#### 6.1.1 前置条件
- 租户已在平台端开通「自助取还」能力
- 门店已创建并处于激活状态

#### 6.1.2 配置规则约束
1. **唯一性约束**：1个门店仅允许存在1条自助取还区域配置规则
2. **服务范围**：固定为门店中心点100km半径范围，不允许修改
3. **地图展示**：
   - 门店位置需显著标识
   - 服务区域用绿色圆圈表示（100km半径）
   - 非服务区域用红橙色多边形表示

#### 6.1.3 新增配置流程
1. 选择门店（支持多选，可批量为多个门店创建相同配置）
2. 系统校验所选门店是否已存在配置
   - 若所有门店均已存在配置，提示"所选门店均已存在配置，请编辑现有配置"
   - 若部分门店已存在配置，提示"以下门店已存在配置：[门店列表]，将跳过这些门店"
   - 若所有门店均未配置，继续下一步
3. 配置定价规则（见6.2）
4. 配置营业时段（见6.4）
5. 配置非服务区域（可选，见6.3）
6. 配置暂停营业时段（可选，见6.4.3）
7. 保存配置（为每个未配置的门店创建独立的配置记录）

### 6.2 定价规则配置

#### 6.2.1 定价模式
采用**基础价 + 阶梯按公里计价**模式：
- **基础价**：第一档距离范围（默认0-10km），固定价格
- **阶梯价**：超出基础价范围后，按公里数分段计费

#### 6.2.2 配置规则
1. **基础价配置**（必填）：
   - 距离范围：(0, 10]km（默认，可修改上限）
   - 计价类型：固定价（fixed）
   - 价格：如500日元
   - 说明：左开右闭区间，表示 0 < distance ≤ 10

2. **阶梯价配置**（可选，支持多档）：
   - 距离范围：如(10, 30]km、(30, 100]km
   - 计价类型：按公里计价（per_km）
   - 价格：如每公里5日元、每公里3日元
   - 说明：左开右闭区间，表示 10 < distance ≤ 30

3. **约束条件**：
   - 定价范围不超过100km
   - 距离范围不能重叠
   - 必须连续覆盖（无间隙）
   - 区间类型：左开右闭 (distance_from, distance_to]

#### 6.2.3 计价逻辑
自助取还费用 = 基于（取车点到门店距离 + 还车点到门店距离）× 2，匹配对应的定价规则

**说明**：
- **投递距离**：门店 → 取车点（需要将车辆送到客户取车位置）
- **收车距离**：还车点 → 门店（需要将车辆从还车位置收回门店）
- **计费距离** = (投递距离 + 收车距离) × 2
- 乘以2是因为投递和收车两个环节都需要计入服务成本

**计算示例**（基于左开右闭区间）：
```
假设定价规则：
- (0, 15]km：500日元（基础价）
- (15, 30]km：每公里20日元
- (30, 100]km：每公里25日元

场景：取车点距门店50km，还车点距门店20km
单程总距离 = 50 + 20 = 70km
计费距离 = 70km × 2 = 140km

计算（左开右闭区间匹配）：
- 基础价 (0, 15]km：500日元
- (15, 30]km：15km × 20 = 300日元
- (30, 100]km：70km × 25 = 1750日元
- (100, 140]km：40km × 25 = 1000日元（按最高档继续计算）
- 总费用 = 500 + 300 + 1750 + 1000 = 3550日元

注：距离匹配规则为左开右闭，例如距离为15km时，匹配 (0, 15] 区间；距离为15.1km时，匹配 (15, 30] 区间
```

**距离计算方式**：
- 使用Google API路径规划计算的车辆行驶最短距离（导航距离）

### 6.3 非服务区域配置

#### 6.3.1 功能说明
在100km服务范围内，排除特定不提供服务的区域。每个非服务区域必须关联到特定门店。

#### 6.3.2 配置方式
1. **选择门店**：
   - 在配置非服务区域前，必须先选择关联的门店
   - 系统自动将地图视图缩放（zoom）到该门店位置
   - 显示该门店的100km服务半径范围（绿色圆圈）

2. **绘制非服务区域**：
   - 使用画笔工具在地图上绘制多边形区域
   - 绘制范围建议在门店100km半径内
   - 支持为同一门店绘制多个非服务区域
   - 非服务区域以红橙色显示

3. **命名与保存**：
   - 为非服务区域输入名称（如"热河区"、"Airport Restricted Zone"）
   - 保存后与选定门店关联

#### 6.3.3 业务规则
- 非服务区域内的POI搜索不展示该门店资源
- 已存在的订单不受影响
- 非服务区域仅对关联的门店生效

#### 6.3.4 多门店服务区域交集处理
当多个门店的100km服务范围存在交集时：

**场景1：交集区域无非服务区限制**
- 客户在交集区域搜索时，展示所有覆盖该区域的门店资源
- 系统按距离、价格等因素排序展示

**场景2：交集区域被某门店设为非服务区**
- 若POI位置在门店A的非服务区内，则不展示门店A的资源
- 若POI位置不在门店B的非服务区内，则正常展示门店B的资源
- 非服务区配置仅影响关联门店，不影响其他门店

**示例**：
```
门店A（东京浅草桥店）和门店B（成田机场店）的100km服务范围存在交集。
- 门店A将"机场限制区"设为非服务区
- 客户在"机场限制区"内搜索：
  - 不展示门店A的资源（因为在其非服务区内）
  - 正常展示门店B的资源（因为不在其非服务区内）
```

### 6.4 营业时段配置

#### 6.4.1 功能说明
支持两种时段配置：
1. **常规营业时段**：设置门店的日常营业时间（非营业时段）
2. **暂停营业时段**：设置临时性的停止服务时间段

#### 6.4.2 常规营业时段配置

**配置选项**：
- **7×24小时服务**：选择此项后，全天候接受自助取还订单
- **自定义营业时间**：按星期设置每日营业时段

**配置示例**：
```
周一至周五：08:00 - 22:00
周六至周日：09:00 - 20:00
```

**业务规则**：
- 非营业时段内不接受新的自助取还订单
- 已存在的订单不受影响
- 客户搜索时，系统自动过滤非营业时段的门店

#### 6.4.3 暂停营业时段配置

**配置项**：
- 开始日期（yyyy-MM-dd）
- 结束日期（yyyy-MM-dd）
- 暂停原因（可选，如"春节维护"、"设备检修"）

**配置示例**：
```
暂停时段：2025-12-01 至 2025-12-03
暂停原因：春节维护
```

**业务规则**：
- 暂停时段优先级高于常规营业时段
- 暂停时段内不接受新的自助取还订单
- 已存在的订单不受影响
- 支持配置多个暂停时段
- 可跨天、跨周、跨月配置
- **暂停时段不允许重叠**：新增暂停时段时，系统需检查是否与已存在的暂停时段有日期重叠，若重叠则保存失败

#### 6.4.4 时段优先级
```
暂停营业时段 > 常规营业时段
```

**判断逻辑**：
1. 首先检查是否在暂停营业时段内，若是则不提供服务
2. 若不在暂停时段内，再检查是否在常规营业时段内
3. 若is_24_7=true，则全天候提供服务

### 6.5 车辆准备时间配置

#### 6.5.1 功能说明
车辆准备时间是指一辆车衔接两个订单中间的最小整备时间，包括：
- 收车环节：从还车点收回车辆到门店
- 整备环节：车辆清洁、检查、加油/充电
- 投递环节：将车辆从门店投递到下一个取车点

#### 6.5.2 配置规则
**默认值**：6小时
**可配置范围**：2-24小时
**配置单位**：小时（整数）

**配置示例**：
```
门店类型：市区门店
车辆准备时间：6小时

门店类型：机场门店
车辆准备时间：8小时（考虑机场距离较远）
```

#### 6.5.3 业务规则
1. **订单排期约束**：
   - 订单A还车时间 + 车辆准备时间 ≤ 订单B取车时间
   - 系统在接受新订单时，自动检查车辆可用性

2. **与到店订单的区别**：
   - 到店订单：车辆准备时间通常为2小时（门店内整备）
   - 自助取还订单：车辆准备时间默认6小时（包含收车和投递时间）

3. **时间计算示例**：
   ```
   订单A：还车时间 2025-12-01 10:00
   车辆准备时间：6小时
   最早可接受订单B的取车时间：2025-12-01 16:00
   ```

4. **特殊场景处理**：
   - 如果还车位置距离门店较远（如>50km），系统可提示延长准备时间
   - 节假日期间可临时调整准备时间（通过暂停营业时段实现）

#### 6.5.4 系统影响
- **库存管理**：影响车辆可售时段的计算
- **订单接受**：系统自动过滤不满足准备时间要求的订单
- **调度优化**：为未来的智能调度预留配置接口

### 6.6 自助取还服务搜索逻辑

#### 6.6.1 服务范围判断
1. POI位置在门店中心点100km半径范围内
2. POI位置不在该门店的非服务区域内
3. 搜索时间在该门店的营业时段内（非暂停营业时段，且符合常规营业时间）

#### 6.6.2 Add-on展示逻辑
- **场景1**：POI在门店常规服务范围内（如10km内）
  - 自助取还作为可选Add-on展示
  - 资源打上「自助取还」标签

- **场景2**：POI超出门店常规服务范围但在自助取还范围内（如10-100km）
  - 自助取还作为必选Add-on
  - 资源打上「自助取还」标签

#### 6.6.3 MVP版本还车位置约束
1. **单POI搜索**（仅指定取车位置）：
   - 允许还车位置 = 取车POI点附近500米内 OR 门店100米内

2. **双POI搜索**（指定取车和还车位置）：
   - 取车和还车POI均在同一门店自助取还服务范围内
   - 允许还车位置 = 还车POI点附近500米内 OR 门店100米内

**说明**：以上逻辑在MVP阶段可覆盖90%以上的自助取还客户租车场景。




## 7. 边界场景与处理

### 7.1 配置相关

| 场景 | 处理方式 |
|------|----------|
| 批量新增时所有门店均已存在配置 | 提示"所选门店均已存在配置，请编辑现有配置"，不允许保存 |
| 批量新增时部分门店已存在配置 | 提示"以下门店已存在配置：[门店列表]，将跳过这些门店"，仅为未配置的门店创建配置 |
| 门店已存在自助取还配置时尝试新增 | 提示"该门店已存在配置，请编辑现有配置"，引导至编辑页面 |
| 定价规则距离范围存在间隙 | 保存时校验失败，提示"距离范围必须连续覆盖" |
| 定价规则距离范围重叠 | 保存时校验失败，提示"距离范围不能重叠" |
| 定价规则超过100km | 保存时校验失败，提示"定价范围不能超过100km" |
| 未配置基础价（第一档） | 保存时校验失败，提示"必须配置基础价" |
| 非服务区域超出100km服务范围 | 允许绘制，但仅在100km范围内生效 |
| 非服务区域未关联门店 | 保存时校验失败，提示"必须选择关联门店" |
| 未选择营业时段类型 | 保存时校验失败，提示"必须选择7×24小时服务或配置营业时间" |
| 自定义营业时间但未配置时间表 | 保存时校验失败，提示"请配置每周营业时间" |
| 暂停时段结束日期早于开始日期 | 保存时校验失败，提示"结束日期不能早于开始日期" |
| 暂停时段与已存在时段重叠 | 保存时校验失败，提示"暂停时段不能重叠，已存在重叠时段：[时段列表]" |
| 自定义营业时间但未配置时间表 | 保存时校验失败，提示"请配置每周营业时间" |
| 暂停时段结束日期早于开始日期 | 保存时校验失败，提示"结束日期不能早于开始日期" |

### 7.2 搜索与订单相关

| 场景 | 处理方式 |
|------|----------|
| POI位置在某门店的非服务区域内 | 不展示该门店资源，但可能展示其他门店资源（若POI在其他门店服务范围内且不在其非服务区） |
| POI位置在多个门店服务范围的交集区域 | 展示所有覆盖该区域且未将其设为非服务区的门店资源，按距离、价格排序 |
| 搜索时间在门店非营业时段内 | 不展示该门店资源，或提示"该时段暂停服务" |
| 搜索时间在门店暂停营业时段内 | 不展示该门店资源，或提示"该时段暂停服务（原因：春节维护）" |
| 取车点和还车点分属不同门店服务范围 | MVP版本不支持，提示"取还车位置需在同一门店服务范围内" |
| 还车位置超出允许范围（500米/100米） | 订单创建时校验失败，提示"还车位置超出允许范围" |
| 实际还车位置与预定位置不符 | 按实际还车位置重新计算费用，差额通过预授权押金抵扣或off session支付 |
| POI在交集区域，多个门店均可服务 | 系统展示所有可服务门店，客户可选择，默认推荐距离最近或价格最优的门店 |

### 7.3 计费相关

| 场景 | 处理方式 |
|------|----------|
| 单程总距离超过100km | 计费距离=单程距离×2，按最高档（如30-100km档）的单价继续计费至实际距离 |
| 计费距离超过定价规则最大范围 | 超出部分按最高档单价继续计算（如定价规则最高到100km，实际计费距离140km，则100-140km按最高档单价计算） |
| Google API路径规划失败 | 使用直线距离 × 1.3系数作为备用计算方式 |
| 费用超出预授权押金额度 | 通过off session支付补扣差额，若失败则标记订单异常 |
| 客户取消订单 | 根据取消政策退款，自助取还费用按比例退还 |

### 7.4 设备与技术相关

| 场景 | 处理方式 |
|------|----------|
| 车机设备离线 | 无法开启自助取还，提示"设备离线，请联系客服" |
| H5页面加载失败 | 提供重试机制，3次失败后提示联系客服 |
| 支付失败 | 允许重试，记录失败原因，必要时转人工处理 |
