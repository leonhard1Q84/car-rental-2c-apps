# 车辆读数检查点

> **版本**：v1.2  
> **最后更新**：2026-08-28  
> **适用范围**：Customer 自助取还与 Store Ops 常规取还、投递、收车核验

## 1. 目标与边界

车辆读数检查点用于在租赁履约的特定时点保存里程及油量／电量。它不是车辆主档的当前值，也不是单纯的车机自动填充结果。

每个检查点必须分别保存：

1. 本次读取到的原始车机快照；
2. 用户对读数的确认、修正或人工填写决定；
3. 本业务节点后续使用的最终读数；
4. 操作人、操作时间、证据与幂等信息。

用户修正不得覆盖原始车机快照，也不得直接反写车辆主档。车辆主档校准由独立的数据对账流程负责。

## 2. 业务检查点

| `checkpointType` | 业务节点 | 最终读数用途 |
|---|---|---|
| `REGULAR_PICKUP` | 常规取车登记 | 租赁起始基准 |
| `REGULAR_RETURN` | 常规还车登记 | 还车与费用结算依据 |
| `SELF_SERVICE_DELIVERY` | 自助车辆投递 | 投递时点基准 |
| `SELF_SERVICE_CUSTOMER_PICKUP` | 承租人自助取车 | 承租人接车确认值 |
| `SELF_SERVICE_CUSTOMER_RETURN` | 承租人自助还车 | 承租人还车确认值 |
| `SELF_SERVICE_COLLECTION` | 门店自助收车核验 | 回收时点轻量复核值 |

相邻检查点相互对比，但不得相互覆盖。

## 3. 读取准入

车机读数只有同时满足以下条件时，才能作为自动建议值：

- 车辆已安装并绑定车机；
- 设备在线且本次请求成功；
- 设备绑定车辆与当前订单车辆一致；
- 采集时间不晚于当前时间，且在服务端配置的新鲜度范围内；
- 原始单位可归一化；
- 数值在合法范围内；
- 与上一履约检查点不存在不可能的连续性冲突。

`hasTelematics=true` 或设备在线只表示具备读取前提，不等于本次读数可用。里程与能源读数必须独立判定，允许部分成功。

试点配置建议：单次读取超时 5 秒、数据新鲜度 120 秒。阈值必须由服务端按市场、供应商与车型配置。

## 4. 状态与失败原因

检查点读取状态：

- `FULL`：里程和能源均有效；
- `PARTIAL`：只有部分字段有效；
- `UNAVAILABLE`：没有可自动使用的字段。

单字段状态：

- `VALID`
- `MISSING`
- `STALE`
- `OUT_OF_RANGE`
- `UNSUPPORTED`
- `ERROR`

不可读取原因：

- `NO_DEVICE`
- `DEVICE_OFFLINE`
- `TIMEOUT`
- `PROVIDER_ERROR`
- `STALE_READING`
- `INVALID_READING`
- `FIELD_UNSUPPORTED`
- `DEVICE_VEHICLE_BINDING_MISMATCH`

用户决定：

- `CONFIRMED`：车机建议值未经修改；
- `CORRECTED`：用户修改了至少一个自动读取字段；
- `MANUAL_REQUIRED`：没有可用自动读数，用户人工填写。

## 5. 能源字段

- 燃油车使用 `FUEL_PERCENT`；
- 纯电动车使用 `BATTERY_SOC_PERCENT`；
- 插混／混动车由车型能源策略决定主确认字段；
- 业务标准值统一为 `0-100%`；
- `N/8` 仅是燃油车 UI 映射，不是唯一存储格式；
- 原始值、原始单位与归一化值必须同时保留。

## 6. Canonical Schema

```ts
type VehicleMetricCheckpointType =
  | 'REGULAR_PICKUP'
  | 'REGULAR_RETURN'
  | 'SELF_SERVICE_DELIVERY'
  | 'SELF_SERVICE_CUSTOMER_PICKUP'
  | 'SELF_SERVICE_CUSTOMER_RETURN'
  | 'SELF_SERVICE_COLLECTION';

type VehicleMetricFieldStatus =
  | 'VALID'
  | 'MISSING'
  | 'STALE'
  | 'OUT_OF_RANGE'
  | 'UNSUPPORTED'
  | 'ERROR';

interface VehicleMetricCheckpoint {
  checkpointId: string;
  checkpointType: VehicleMetricCheckpointType;
  orderId: string;
  vehicleId: string;
  deviceId?: string;
  readingStatus: 'FULL' | 'PARTIAL' | 'UNAVAILABLE';
  unavailableReason?:
    | 'NO_DEVICE'
    | 'DEVICE_OFFLINE'
    | 'TIMEOUT'
    | 'PROVIDER_ERROR'
    | 'STALE_READING'
    | 'INVALID_READING'
    | 'FIELD_UNSUPPORTED'
    | 'DEVICE_VEHICLE_BINDING_MISMATCH';
  telemetrySnapshot?: {
    provider: string;
    capturedAt: string;
    receivedAt: string;
    mileage?: {
      status: VehicleMetricFieldStatus;
      rawValue?: number;
      rawUnit?: string;
      normalizedKm?: number;
    };
    energy?: {
      status: VehicleMetricFieldStatus;
      kind?: 'FUEL' | 'BATTERY';
      rawValue?: number;
      rawUnit?: string;
      normalizedPercent?: number;
    };
  };
  decision: 'CONFIRMED' | 'CORRECTED' | 'MANUAL_REQUIRED';
  finalMetrics: {
    mileageKm: number;
    energyKind: 'FUEL' | 'BATTERY';
    energyPercent: number;
  };
  correctedFields?: Array<'MILEAGE' | 'ENERGY'>;
  correctionReason?: string;
  evidenceAttachmentIds?: string[];
  actorId: string;
  actorRole: string;
  confirmedAt: string;
  version: number;
  idempotencyKey: string;
}
```

## 7. 交互契约

### 7.1 全部读取成功

- 显示里程、油量／电量、来源和读取时间；
- 自动值直接进入可编辑字段，用户仅在有误时修改；
- 车辆读数模块启用时，仪表盘照片仍为必填现场证据，不因车机完整读取而省略；
- 车辆读数区不设置“数据无误”“修改数据”或“确认车辆读数”等独立按钮；
- 当前业务页面的最终主提交动作同时确认车辆读数，并生成当前节点检查点；
- 自动值未经修改时生成 `CONFIRMED`，任一自动字段被修改时生成 `CORRECTED`。

### 7.2 部分读取成功

- 有效字段自动填入可编辑字段；
- 缺失字段由用户填写；
- 不得使用车辆主档、历史订单字段或相邻检查点补齐本次缺失字段；
- 最终业务提交形成 `CORRECTED` 检查点，并保留成功读取字段与人工补充字段的来源差异。

### 7.3 无法读取

- 未安装车机时仅提供人工填写，不展示“重新读取”；
- 已安装车机但离线、超时或读取失败时，只有接入真实重新读取能力才展示“重新读取”，不得使用纯延时模拟读取；
- 里程与油量／电量初始值保持为空，不得从车辆主档、历史订单或相邻检查点生成默认值；
- 车机故障不得阻断取车或还车；
- Customer 端只展示友好说明，Store Ops 可展示可操作的失败原因。

### 7.4 修正

- 输入框以车机值为初值；
- 用户直接修改有误字段，不增加读数区内的中间确认步骤；
- 最终业务提交时对比车机原值与最终值；
- 修正字段标记为 `CORRECTED`；
- 仪表盘照片在车辆读数模块启用时已经必填，修正或人工填写不得改变该要求；
- 影响费用或与其他数据源冲突时进入人工复核。

### 7.5 仪表盘照片

- 仪表盘照片只作为读数证据，不作为 OCR 或其他自动识别输入；
- 上传、替换或删除照片不得改变里程与油量／电量字段；
- 车辆读数模块在业务节点启用时，仪表盘照片始终显示且必须上传；完整车机读取、部分读取、读取失败、人工填写和修正场景不得降低该要求；
- 仪表盘照片缺失、上传中或上传失败时，当前业务节点的最终主提交动作必须阻断，并在照片入口附近提供可恢复的错误提示；
- 历史 payload 中的 OCR 字段可以只读兼容，新提交不得生成 OCR 结果。

## 8. 数据来源边界

当前六个取还车节点只接受车机读取和人工填写两类来源。仪表盘照片仅作为证据，不引入 OCR 来源仲裁。相邻检查点只用于连续性校验与差异展示，不得作为本次实时车机读数或静默默认值。费用、合同和履约状态只使用最终业务提交生成的 `finalMetrics`。

## 9. 连续性与结算

- 还车里程不得小于取车最终里程；
- 自助取车里程不得明显小于投递里程；
- 收车里程不得明显小于承租人还车里程；
- 能源百分比必须处于 `0-100`；
- 设备绑定不一致时拒绝自动使用数据；
- 承租人修正、来源冲突或连续性异常时，结算状态进入 `PENDING_REVIEW`；
- 无修正、无冲突且连续性正常时，是否自动结算由租户风控策略决定。

## 10. 验收标准

```gherkin
Scenario: 完整车机读数随业务页面提交
  Given 当前车辆绑定在线车机且本次里程和能源读数有效
  When 用户进入需要采集车辆读数的业务节点
  Then 页面显示车机读数、来源和读取时间
  And 页面要求上传当前业务时点的仪表盘照片
  And 仪表盘照片缺失时最终业务提交被阻断
  And 车辆读数区不显示独立确认或修改按钮
  And 用户提交当前业务页面时生成 CONFIRMED 检查点
  And 提交记录同时保留 telemetrySnapshot 与 finalMetrics

Scenario: 单字段读取失败
  Given 车机里程有效但能源读数不可用
  When 页面完成本次读取
  Then 里程保持自动读取值
  And 用户只需填写能源字段
  And readingStatus 为 PARTIAL

Scenario: 车机不可读取时人工降级
  Given 车辆未安装车机或设备离线或本次读取失败
  When 用户进入车辆读数区域
  Then 页面说明无法自动读取
  And 未安装车机时不显示重新读取
  And 字段保持为空且提供人工填写与仪表盘证据入口
  And 用户可以人工填写并继续流程
  And decision 为 MANUAL_REQUIRED

Scenario: 人工修正不覆盖原始值
  Given 页面已经展示有效车机读数
  When 用户修改任一字段并提交当前业务页面
  Then decision 为 CORRECTED
  And telemetrySnapshot 保持原始值
  And finalMetrics 保存用户确认后的值
```
